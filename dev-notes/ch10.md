## 阶段 0: Brainstorm 定稿

- **用户关键原话**:
  > "我要用 Superpowers 模式给客服系统训练一个自己的模型:微调一个多标签主题分类器,把飞轮攒下的低置信度问题按主题批量归类,好决定先补哪块知识。"
  > "1. 数据处理四步...归并术语表:全系统统一一份 17 类的权威类目表,退换货、物流、尺码、发票四大类领头...近邻边界:修归保修维修、退归退换货;运费管钱、物流管货;价保是补差价、优惠活动是券和满减...分层抽样:按 80/10/10 划训练、验证、测试集...数据增强:同义词替换、句式微调,只扩训练集"
  > "2. 标注:多标签,一句话字面提到几个诉求就打几个标签,一个不多一个不少;标签获取走大模型照术语表预标、人工抽审这条折中路线"
  > "3. 训练:RoBERTa-wwm-ext 全参微调,不用 LoRA;训练中用验证集盯分数,配正则化和早停防过拟合"
  > "4. 评测:留出测试集上按类目算精确率、召回率、F1,配每类目混淆矩阵;自动指标之外,再人工抽判错样本复核"
  > "5. 部署:导出成推理服务,挂在旁路按批量跑——低置信度问题攒够一批归一次类,结果写进 topic_classifications 表(关联问题、多标签 labels、归类时间)喂给飞轮后台看各主题分布;实时对话主链路不调它"
  > "6. 前端配套:在飞轮后台加一个主题分布页,各类目问题量做成简单图表,哪类堆得多一眼能看出来"
  > 澄清问题 1：“使用'D:\PycharmProjects\AstroBot\mewhelp-ch10-dataset'中的数据集”
  > 澄清问题 2：“选项 A”（在当前主环境安装 torch 和 transformers）
  > 方案调整原话：“基于方案2对以下方案进行合理调整：部署:ONNX + 独立推理服务 + 旁路批处理...1 ONNX 导出: torch.onnx.export 导出(dynamic axes 支持变长 batch)...校验 ONNX 与 torch 预测一致...2 推理服务(独立进程 :8110): FastAPI + onnxruntime + tokenizers,不依赖 torch/transformers...3 旁路批处理(主链路不碰): scripts/classify_pool.py...「攒够一批归一次」:默认 --min-batch 10...重跑幂等...”
  > 评测优化原话：“容错红线按档位设闸,不是每类一条线:严(F1 ≥ 0.9)、中(≥ 0.8)、宽(不设线,画 —)...判错样本导出人工复核:data/ch10/reports/error_samples.md...按错误方向归类(漏打/多打/错位)...判定阈值可复算:scan_threshold_replay.py 重演训练时的阈值扫描...”
  > 验收前端原话：“九项实证按关注点拆四页,各自独立路由(/acceptance, /acceptance/eval, /acceptance/data, /acceptance/errors)...API: app/api/acceptance.py...只读端点...闸门三态(pass/fail/missing)...三份考卷泄漏自检是硬闸...就地重跑:app/core/jobs.py 白名单作业运行器 + app/api/jobs.py...共享外壳 app/static/acceptance.css + acceptance.js...这五页(含主题分布)是后台管理的一部分...”

- **关键产出**:
  - Spec 设计规范路径: `docs/superpowers/specs/2026-09-19-ch10-multilabel-topic-classifier-design.md`
  - Git Commit: `8f67944` (`docs(spec): add chapter 10 multilabel topic classifier and acceptance design spec`)
  - 核心架构决议:
    1. **17 类权威术语表与近邻边界定义**：退换货、物流、尺码、发票领头，明确修归保修/退归退换、运费管钱/物流管货、价保补差/优惠满减边界；
    2. **数据零泄漏自检硬闸**：训练集、验证集、测试集文本交集必须严格为 0；
    3. **模型微调与早停**：RoBERTa-wwm-ext 全参微调，多标签 `BCEWithLogitsLoss`，监控验证集 Macro-F1 早停（`patience = 3`）；
    4. **三档分级红线与错因记账**：严档 F1 $\ge 0.9$、中档 F1 $\ge 0.8$、宽档画 `—`；错因细分为漏打（放跑 +1）、多打（冤枉 +1）、错位（放跑 +1 & 冤枉 +1），错例条数与混淆矩阵笔数精确数学闭环；`scan_threshold_replay.py` 9 候选线扫描复算；
    5. **ONNX 独立推理服务 (:8110)**：动态轴导出，Logits 容差 + 标签 100% 一致性硬闸；FastAPI + onnxruntime + tokenizers 轻量服务，PID 管理，无 torch/transformers 依赖；
    6. **旁路批处理归类流水线**：`classify_pool.py` 未归类记录批量拉取，`--min-batch 10` 批次闸门，幂等写入 `topic_classifications`；
    7. **五页后台看板与九项实证验收体系**：`/topic-distribution` 及 `/acceptance` 4 页面，只读 `/api/acceptance` 接口，中立白名单作业运行器 `/api/jobs`，纯 HTML/CSS 视觉交互。

- **用户拒绝或纠偏**:
  - 拒绝初始推荐的方案 1（PyTorch 原生流水线），明确纠偏为方案 2（ONNX 导出 + 独立轻量推理服务 :8110 + 旁路批处理）；
  - 纠偏评测设闸方式：不采用统一样条线，而是按知识库优先级影响分严（0.9）、中（0.8）、宽（—）三档，宽档标 `—` 防误导；
  - 补充错因三向归因机制（漏打、多打、错位）与混淆矩阵笔数平衡闭环；
  - 补充 9 候选线阈值复算脚本 `scan_threshold_replay.py`；
  - 补充完整的九项实证验收前端 4 页架构及 API 规范、三态闸门、零泄漏硬闸、白名单安全作业运行器。

- **翻车与返工**:
  - 无。
