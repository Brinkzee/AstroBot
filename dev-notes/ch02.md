  > "5. 只做单轮调用:模型调一次工具就收敛"

- **关键产出**:
  - Spec 文档路径: `docs/superpowers/specs/2026-09-07-function-calling-toolchain-design.md`
  - 任务追踪工件: `C:\Users\Brinkzee\.gemini\antigravity\brain\8c03982a-40a5-4d49-aeaa-e18c567f60ba\task.md`
  - 架构决议:
    1. 数据访问选用异步架构：`AsyncEngine` + `AsyncSession` + `aiomysql`，保持高并发与流式生成非阻塞；

- **用户拒绝或纠偏**:

- **翻车与返工**:
  - **踩坑 1（aiomysql 0.3.2 ping 参数异常）**: 使用 SQLAlchemy 2.0 `create_async_engine` 开启 `pool_pre_ping=True` 时，底层 `aiomysql.connection.ping()` 抛出 `missing 1 required positional argument: 'reconnect'`。定位为该驱动版本与连接池预检适配问题，调整为 `pool_pre_ping=False` 并依赖 `pool_recycle=3600` 进行长连接管理，彻底排除了连接异常。
  - **踩坑 2（WSL2 代理提示与 NAT 端口警告）**: 在宿主机配置了网络代理时，WSL2 NAT 模式会在启动时输出乱码提示（`wsl: 检测到 localhost 代理已配置，但未镜像到 WSL...`）。通过在宿主机 `~/.wslconfig` 中开启 `[wsl2]` 的 `networkingMode=mirrored`，网络栈与宿主机完全镜像打通，消除端口转发警告并提升连接性能。
  - **踩坑 3（WSL2 空闲休眠导致 MySQL 掉线）**: 当没有交互式终端打开时，WSL2 默认会在无前台进程时自动休眠（`Received SHUTDOWN from user <via user signal>`），导致 Docker MySQL 随之关闭，触发 `OperationalError: (2013, 'Lost connection to MySQL server during query')` 或 `2003`。通过封装 `scripts/wsl_helper.py`，在 Python 执行入口处建立进程级保活守护并自动探测 3306 端口与容器自愈拉起，彻底解决了掉线问题。
  - **踩坑 4（Windows 控制台 GBK 编码）**: Windows 控制台默认代码页为 936 (GBK)，脚本打印特殊 Unicode Emoji（如 `\u2705`）会触发 `UnicodeEncodeError`。已在 `scripts/wsl_helper.py` 中增加标准输出 UTF-8 重定向，并将日志标识替换为通用方括号文本（如 `[OK]`, `[WARN]`）。
