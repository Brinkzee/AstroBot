## 阶段 0: Brainstorm 定稿

- **用户关键原话**:
  > "我要用 Superpowers 模式把客服系统升级成生产级架构:Workflow 确定性编排做骨架,主力 Agent 作为骨架里的核心节点。"
  > "1. 祛魅热身:先不用框架,手写一遍最裸的 Agent 循环(调 LLM,有工具调用就执行并把结果喂回去,没有就收敛出答案),看清它就是个带工具的循环,再用 LangGraph 重构"
  > "2. 图骨架按这条流程搭:指代消解、意图识别、按意图分流、知识检索、置信度闸、主力 Agent、日志记录"
  > "3. 分流规则写死在代码里,把第 6 点的七类意图逐一归到四个出口:知识类(商品咨询、退款退货)强制先做 RAG 检索并过置信度闸;业务数据类(物流、订单、售后)直通 Agent;投诉回安抚话术并不后端自动执行;闲聊固定话术"
  > "4. 主力 Agent 用 ReAct 循环:简单问题一次收敛,复杂问题多走几步,缺信息追问,停止条件和 token 控制"
  > "5. 会话状态用 LangGraph 的 State 一路贯穿,持久化用自带的 checkpointer"
  > "6. 两个节点本章最简实现:指代消解透传,意图识别 7 类输出 JSON"
  > "7. 置信度闸本章做到:卡在检索后、进 Agent 前,证据弱回兜底并记入低置信度表"
  > "8. 转人工、建工单分开做,交用户自选,不后端自动执行"
  > 持久化方案选择：“A”（双轨协同机制，MemorySaver + 既有消息表落盘）
  > 工单触发机制选择：“A”（RESTful 专用接口 POST /api/tickets，转人工前端模拟）
  > 架构方案选择：“采用方案 1”（分层确定性工作流骨架 + 显式 ReAct Agent 闭环）
  > 模块 1~4 详细设计呈现阶段：“确认”

- **关键产出**:
  - Spec 设计规范路径: `docs/superpowers/specs/2026-09-10-workflow-agent-architecture-design.md`
  - 任务追踪工件: `task.md`
  - 关键架构决议:
    1. **分层确定性图骨架（方案 1）**：LangGraph 构建顶层拓扑，外层业务逻辑绝对确定，内层主力 Agent 有限自适应，杜绝流程漂移；
    2. **七类意图四出口硬编码分流**：闲聊（0 Token 固定话术）、投诉（安抚+双按钮建议）、知识类（商品咨询/退款退货强制预检索与置信度闸）、业务数据类（物流/订单/售后直通 Agent）；
    3. **置信度闸门前置拦截**：在流式生成开始前根据检索证据得分（`max_score < 0.35` 或无召回）即时决策，避免流式吐字中途反悔，弱证据沉淀至 `low_confidence_questions` 表；
    4. **退款退货双源决策**：上游预检索注入退换货政策证据，Agent 内部保留调用订单工具查物流/状态权限，实现政策+订单的复合推演；
    5. **建议选项与后端动作解耦**：投诉分支与 Agent 仅下发建议按钮，前端纯模拟「转人工」，独立轻量接口 `POST /api/tickets` 触发「建工单」，两者完全独立且用户可忽略。

- **用户拒绝或纠偏**:
  - 明确持久化采用双轨机制（运行时 LangGraph MemorySaver + 业务 messages 表同步落盘），保证现有历史会话 API 与前端兼容；
  - 明确建工单通过独立 REST API 触发，转人工由前端纯模拟，不产生额外 LLM 消耗。

- **翻车与返工**:
  - 初始安装 `langgraph` 时，pip 解析器下载了 `langchain-core 1.6.2` 引起与 `langchain 0.3.30` 的冲突警告。经实际导入与既有 18 项单测回归验证，核心 `StateGraph`、`MemorySaver` 及业务工具链全部正常运行，无运行时阻断；
  - `write_to_file` 工具调用时初次误向项目代码路径传入了 `ArtifactMetadata` 导致参数校验报错，立即纠正参数调用规范并成功生成 Spec 文件。

## 阶段 2: Task 1 完成（祛魅热身 - 纯手写裸 Agent 循环与单测验证）

- **用户关键原话**:
  > "1. 祛魅热身:先不用框架,手写一遍最裸的 Agent 循环(调 LLM,有工具调用就执行并把结果喂回去,没有就收敛出答案),看清它就是个带工具的循环,再用 LangGraph 重构"

- **关键产出**:
  - 代码实现: `scripts/bare_agent_loop.py`
  - 单元测试: `tests/test_bare_agent_loop.py`（3 项测试 100% PASS，包含同步/异步工具支持、单步收敛与步数防御截断）
  - Git Commit: `b1a6335` (`feat(agent): implement bare agent loop for framework demystification`)
  - 独立代码审查: Spec Compliance: Spec ✅, Code Quality: Approved
  - 核心成果:
    1. 脱离任何 Agent 框架，纯靠 `while steps < max_steps` 循环，实现对 LLM 响应中 `tool_calls` 的解析、动态工具派发调用（支持同步/异步工具函数自适应）、将 `ToolMessage` 追加回消息列表，自发驱动下一轮推理；
    2. 模型未发起工具调用时直接收敛返回答案；
    3. 达到 `max_steps=5` 时触发防御机制，向模型发起不带工具绑定的总结指令，强制产出最终答复，杜绝死循环；
    4. 单测不依赖外部网络与 API Key，通过 `AsyncMock` 模拟大模型连续响应，0.07s 完成确定性验证。

- **用户拒绝或纠偏**:
  - 无。

- **翻车与返工**:
  - 在编写单测 `test_bare_agent_loop_single_step_convergence` 断言时，测试注释中写明共 5 条消息（`system + human + ai(tool_call) + tool + ai(final)`），但在原 assert 中笔误写成了 `len == 4`。实现者在 TDD 执行阶段主动纠正为 `len == 5`，审查员确认该修复合理且必要，未造成流程返工。
