- **用户关键原话**:
  > "我要用 Superpowers 模式给客服系统建知识库,把 query_faq 的内部实现从关键词查表升级成向量语义检索,工具的入参出参契约保持不变。"
  > "1. 离线建库·文档处理:知识文档(退货政策、商品 FAQ、售后手册这类 Markdown)按标题层级做结构感知切分;超长内容递归切;块间加重叠且裁到最近句号,不留半截话;大表格按行切时每块都复制表头"
  > "2. 离线建库·对话挖知识:做一条从历史客服对话挖知识的定时任务,分批喂给 LLM 抽取问答对,先进暂存表、再整体去重入库"
  > "3. 落库结构:每条知识带 category、questions、answer 三个字段,拼成一段文本做向量化;商品 FAQ 和挖出来的问答对,questions 填真实问法;政策手册这类没有天然问题的,questions 填所在章节标题、category 填上级标题路径;另带章节路径、内容类型、是否关键条款、前后块指针四类元数据,只存不进向量"
  > "4. 双写落库:MySQL 建 knowledge_chunks 表当原文权威源、Milvus 建 knowledge 集合;先写 MySQL 记「待向量化」,再写 Milvus 拿 vector_id 回填、状态转「已向量化」;按主键幂等,挂了能重跑"
  > "5. 在线检索:问题向量化后到 Milvus 按相似度取 Top-K,替换掉 query_faq 的关键词查表实现"
  > "milvus用milvus lite嵌入式，BGE-M3用huggingface的，token我存在了.env里"
  > "规范化目录+现有数据源，markdown文档存放在data/kb/目录下；历史对话读取采用推荐方法"
  > "采用方案1"
  > 模块 1~5 分段设计呈现阶段：“确认”

- **关键产出**:
  - Spec 设计规范路径: `docs/superpowers/specs/2026-09-08-rag-knowledge-base-design.md`
  - Git Commit: `aa5a2fd` (`docs(spec): add design spec for ch03 rag knowledge base and vector retrieval`)
  - 任务追踪工件: `C:\Users\Brinkzee\.gemini\antigravity\brain\d554b5a1-39b9-4735-8ae7-a81b006c79e9\task.md`
  - 关键架构决议:
    1. **数据层解耦与双库对齐**：MySQL `knowledge_chunks` 作为原文权威源，Milvus-Lite `knowledge` 集合作为向量索引，两端主键 `id` 1:1 数值完全对齐，从根源消除分布式 ID 映射错位；
    2. **结构感知与断句对齐算法**：基于栈的 Markdown 标题层级追踪；重叠窗口滑动时强制在最近句子标点（`。！？\n`）后断开，彻底消灭半截话；大表格分块保留表头广播；
    3. **对话挖掘流水线**：分批防串味拉取会话，LLM 结构化抽取问答落 `qa_extraction_staging` 暂存表，两阶段规则与 BGE-M3 语义聚类去重；
    4. **两阶段双写与断点恢复**：`pending` 落 MySQL $\to$ BGE-M3 向量化 $\to$ Milvus upsert $\to$ 回填 `vector_id` 状态转 `done`；提供 `repair_pending_chunks` 自动捡起漏向量化数据，满足中断重跑验收要求；
    5. **检索契约兼容**：`query_faq` 入参出参及 Docstring 保持 100% 契约不变，内部替换为 Dense 向量相似度 Top-3 余弦召回。

- **用户拒绝或纠偏**:
  - 用户指定技术组件具体部署形态：Milvus 采用本地嵌入式 `milvus-lite`，BGE-M3 采用 Hugging Face Inference API（复用 `.env` 中的 `HUGGINGFACE_TOKEN`）；
  - 用户明确规范化输入目录：Markdown 知识文档存放于 `data/kb/` 目录；历史对话优先读取 MySQL 现有流水，并兼容补充样例。

- **翻车与返工**:
  - 早期验证 Windows 环境下通过 httpx 直连 Hugging Face API 时频繁出现 `ssl.SSLEOFError`，定位排查出为 Windows 本地系统代理（端口 7897）握手拦截，改用 `huggingface_hub.InferenceClient` 配合官方直连通道后，成功稳定获得 BAAI/bge-m3 1024 维特征向量；
  - 验证 Milvus-Lite 本地数据清理时，直接调用 `os.remove` 触发 `PermissionError [WinError 5]`，深入排查发现 Milvus-Lite 在 Windows 下生成的 `.db` 实际为 SQLite/FAISS 组合的目录结构，已修正为 `shutil.rmtree` 规范目录管理；
  - 初次写入 Spec 文件时因参数混淆携带 `ArtifactMetadata` 导致写工作区报错，迅速定位为非工件目录写限制，去除多余元数据后成功写入并提交 Git。
