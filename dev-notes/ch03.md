- **卡顿排查与深度根因修复**:
  1. **WSL2 会话 premature atexit 误关导致 MySQL 断连**：
     - *根因*：`scripts/wsl_helper.py` 在 `atexit` 中注册了 kill 逻辑。每次短命脚本退出时保活进程被连带杀灭，导致 Windows 11 WSL2 在 8~10 秒空闲后自动挂起（Stopped），后续命令连接 MySQL 3306 发生断连或在握手期间无限挂起。
     - *修复*：改用 Windows `DETACHED_PROCESS` 标志启动独立后台 `wsl` 保活进程，并移除 `atexit` 的误关逻辑，确保整个研发测试周期内 WSL2 及 Docker 容器持续处于稳定运行状态。
  2. **Milvus-Lite 集合生命周期状态保护缺失**：
     - *根因*：跨进程或新建连接访问已有 Milvus-Lite 数据库时，集合可能处于 `'released'` 状态，直接执行 `search` 会报 `MilvusException: code=101, Collection is in state 'released'`；同时 `MilvusKnowledgeStore.close()` 原逻辑会单方面调用 `release_server` 销毁进程内共享 gRPC 端口，造成其它检索器连接被断开（Connection refused）。
     - *修复*：在 `MilvusKnowledgeStore.search()` 和 `count()` 中增加自动 `load_collection()` 状态唤醒机制；并将 `release_server` 改为可选参数，仅在测试销毁临时目录时显式释放，避免共享端口被误杀。
  3. **pytest-asyncio 跨测试函数 Event Loop 隔离与连接池复用冲突**：
     - *根因*：pytest-asyncio 在多个测试函数间切换 event loop 时，SQLAlchemy 异步连接池会复用前一个已关闭 loop 的 MySQL socket 连接，导致 Windows ProactorEventLoop 抛出 `AttributeError: 'NoneType' object has no attribute 'send'`。
     - *修复*：在 `tests/test_ch03_acceptance.py` 中增加 `reset_engine_connections` 自动清理 fixture，在每个测试函数结束后主动调用 `await engine.dispose()` 清理连接池。
  4. **SQL 回退单测隔离**：
     - *根因*：`tests/test_business_tools.py` 中的旧测试假设 Milvus 为空，当建库后 Milvus 有数据时直接命中向量检索导致断言失败。
     - *修复*：为 SQL 回退用例显式打桩 `mock_retriever.retrieve = AsyncMock(return_value=[])`，确保 SQL 回退机制能够被独立纯净验证。
