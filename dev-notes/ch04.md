  > "2. 重排:用 bge-reranker-v2-m3 精排出 Top-10;组装进 prompt 时把最相关的放首尾,别按分数顺序堆中间"

  > "6. 评估体系:造一份带难度梯度、标注 ground-truth 的评估集;检索段评 Recall@K、MRR,生成段评 Faithfulness;跑纯向量、纯 BM25、混合、混合加 Rerank 四种策略的对比,按 query 类型分桶出报告"
  > "7. 前端配套:在现有聊天页上把回答里的引用编号做成可点的,点开能看到来源 chunk 的原文和章节路径;再给每段回答的左下角挂一组满意度反馈(👍/👎),用户点一下就点亮所选、显示「已反馈」并一次性锁定——这条信号先做纯前端采集,为后面的数据飞轮留个入口"
  > "内聚在检索管道内部"
  > "选项A"
  > "采用方案1"
  > "评估集使用tests/data/eval_ch04.jsonl，其他步骤不变"
  > 模块 1~5 分段设计呈现阶段：“确认”

- **关键产出**:
  - Spec 设计规范路径: `docs/superpowers/specs/2026-09-08-hybrid-rag-rerank-eval-design.md`
  - Git Commit: `26b9c31` (`docs(spec): add design spec for ch04 hybrid rag rerank and eval system`)
  - 关键架构决议:
    1. **模块化分层流水线架构（方案 1）**：解耦为 `QueryProcessor`、`MilvusKnowledgeStore`、`BGERerankerClient`、`AdvancedKnowledgeRetriever`、`RAGGenerator`、`RAGEvaluator` 与前端交互模块，保障单测可测性与高内聚性；
    2. **检索管道内聚 Query 理解**：外部保持统一检索契约，内部单次结构化提取标准问法（用于 Dense 向量）与扩展关键词（用于 BM25 全文检索）；
    3. **两阶段受控生成控制（选项 A）**：Top-10 知识重排后先执行轻量结构化自检判定（`useful: bool, reason: str`），不足则直接落库 `low_confidence_questions` 并礼貌拒答，充足则按首尾放置（Lost in the Middle）编排流式生成带 `[n]` 引用角标的回答，杜绝流式中途反悔；
    4. **真实分桶评估集对齐**：采用现有 `tests/data/eval_ch04.jsonl`（300 题，5 大分桶：`A_policy`, `B_model`, `C_colloquial`, `E_multi`, `D_absent`），检索段评估 Recall@K / MRR，生成段评估 Faithfulness，编造个案跨轮幂等管理与复发回退记入 `faith_cases`；
    5. **前端 Vibe 敏捷模式**：引用角标可点展开抽屉溯源、左下角满意度反馈（👍/👎）单次点亮锁定，采用 Vibe 模式敏捷交付。

- **用户拒绝或纠偏**:
  - 评估集指定使用既有的 `tests/data/eval_ch04.jsonl` 文件，无需重新合成随机评估集；
  - 明确 Query 理解必须内聚在检索服务内部，不破坏外部 Agent 工具干净契约；
  - 明确生成自评采用前置轻量判别（选项 A），不采用单次混编生成方案。

- **翻车与返工**:
  - 初始验证 Milvus 2.5 原生中文分词时，按照常规文档使用 `analyzer_params={"type": "chinese"}`，Milvus-Lite 报错 `unknown tokenizer type: 'chinese' (supported: 'standard', 'jieba')`。排查后精准定位并切换为 `analyzer_params={"type": "jieba"}`，实测成功建库并调通 `hybrid_search` 与 `RRFRanker(k=60)`；
  - 初始测试 Hugging Face InferenceClient 调用 `BAAI/bge-reranker-v2-m3` 时，直接尝试 `sentence_similarity` 接口报错 `doesn't support task 'sentence-similarity'. Supported tasks: 'text-classification'`。进一步测试 `text-classification` 接口参数结构，定位到 Cross-Encoder 在 Router 上接收的格式要求为 `inputs: [{'text': q, 'text_pair': doc}, ...]`，经调整后成功获得准确相关性评分，并保留本地测试环境的确定性 Mock 降级支持。

  - **初次独立代码审查被打回 (CHANGES REQUESTED)**：审查员发现 `sql/ch04_ddl.sql` 的 `faith_cases` 字段 COMMENT 中包含 4 处英文分号 `;`，而 `scripts/init_ch04_db.py` 使用了无引号感知的 `cleaned_text.split(";")` 盲目切分，导致 `CREATE TABLE faith_cases` 被切成了 6 段非法 SQL 语法碎片，真实 MySQL 执行将报错崩溃；且原测试断言过宽（`len >= 2`）导致假阳性通过。
